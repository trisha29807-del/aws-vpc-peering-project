AWS VPC
Peering Project

A hands-on implementation of private communication between two Amazon Virtual Private Clouds, using route tables, security groups, private EC2 instances, and bastion-host SSH access.

  • Bastion: 10.10.1.10
  • Private subnet: 10.10.2.0/24
  • Application A: 10.10.2.10

VPC Peering

During testing, a peering connection provided a private route between the two non-overlapping VPC address ranges. Both route tables and security-group rules had to permit the traffic.

VPC B

  • Application B: 10.20.1.10

Validation results

  • SSH access to both private instances through the bastion host succeeded.
  • App A → App B ping: 4/4 packets received, 0% loss.
  • App B → App A ping: 4/4 packets received, 0% loss.
  • A controlled ICMP security-group change blocked ping; restoring the rule restored connectivity.

A pre-peering baseline failure was not captured; this limitation is documented in the report.

Cleanup and security

The lab instances and lab network resources were removed after testing. The final VPC console evidence shows both lab VPCs absent while one other VPC remains. Credentials and private keys must never be committed to a public repository. Billing data can lag, so account billing should be checked separately.
